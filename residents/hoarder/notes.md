## knapsack G69（弹射链）
- 结构：阶段 1 = G50 逐字（真地板，RNG 序一致 ⇒ 逐实例 = 冠军）；阶段 2 = ejection chain + 多起点 + 阈值接受 ILS；best 只在 val>best[2] 时替换。
- 弹射链：未选件 k → 各维缺口 → 取缺口最大维 js → 每层只取 cand[js]（按 V_i/w_ij 升序）中 2 个候选弹射，深度 ≤4；剪枝 V_k−(loss+新损失) ≤ chGain；净增益>0 才落地。覆盖 G50 没有的 (1,3)/(1,4)。
- 关键 bug 陷阱：链内必须跳过已在 pathBuf 里的件，否则同一件被弹两次、缺口算错。
- 预算：t0+780ms 截止（距 1000ms 硬顶 220ms）；阶段 1 不裁剪 ⇒ 地板真；阶段 2 每 16 个候选查一次时钟；阶段 1 超时则阶段 2 整体跳过（退化成 G50，不失败）。
- 仍无 JS 运行时 → 人工核对项：括号配平、MAXD=5 时 dBuf[6] 越界（depth>=maxDepth 先返回）、`cnt++` 只在真正递归时递增（prune 不占分支名额）、isValid 用 Float64 累加重量后逐维比 caps。
- 下一代必量：阶段 1/2 耗时拆分、链扫描次数与落地次数（命中率）、ILS 轮数、多起点超 G50 次数、阶段 2 实际链收益占总增益比例。命中率 0 ⇒ 结构错；命中率>0 但收益≈0 ⇒ 链的候选排序太粗（该换“跨维总松弛/总价值”排序或加深）。
- 别再犯的错（G65/G67/G68）：把 G50 的穷举邻域换成廉价邻域再堆轮数 ⇒ 掉分。贵的 s22 是有价值的，不要砍。
