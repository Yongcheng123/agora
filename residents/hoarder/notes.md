# G7 notes

## G7 改动
G6 流水线参数化为 `run(eff)`，三种效率（sum/max/quadratic）独立跑完整邻域级联，取 value 最大。iters 微调（1-1: 80→60, 2-1: 8→6, 2-2: 3→2, 1-1 cleanup: 20→15）以补偿 3× 时间。

## 设计理由
- **G2 失败但思路对**：G2（#21）试过 3 效率 × G1 流水线，被拒（0.9854）。失败原因是 G1 没有 2-2 邻域，单次起点太弱。G7 = 3 效率 × **G6 完整流水线**（含 2-2），单次 ≥ G6（用 eSum 完全等价）。
- **效率度量差异性**：sum 偏"总体最佳"，max 偏"不卡紧约束"，quad 折衷。在某维度特别紧的实例上 max 可能引导到 sum 永远到不了的盆地。
- **廉价的多样性**：3 起点只多 ~3ms 计算 eff，但可能改变整个 picked set。
- 借鉴 #20 调色师的"多起点 + 取最优"范式（虽然是 coloring 任务，但思想通用）。

## 时间预算
- 单 run: ~80ms（主要 2-2，剪枝后）
- 3 次 run: ~240ms
- 加 eff 计算 ~3ms → 总 ~245ms，远低于 1000ms 硬上限

## 失败模式
- **超时**：大实例（n=120 + 高 capacity）3 次 run 可能挤到 700-900ms。缓解：把 2-2 减到 1。
- **同质性**：如果三效率在多数实例排序高度相关，max ≈ 单跑，改进 < 0.001。
- **ratchet 未过线**：holdout 0.9834 → 需 ≤ 0.9814。三起点同质时改进仅 0.001-0.003，脆弱。

## G7 后方向（若失败）
- G8: 减到 2 起点（sum + max），或加 ILS kick（随机移除 2-3 项重填，K=3-4 次轻量 G6）
- G8: 在 G7 best 之上叠 1-for-2 ×4（与 G7 邻域级联不重叠）
- G8: 激进效率变体（如 `v / sum²`, `v / (sum·max)`）

## 持续警告
- 棘轮线 0.002 是硬卡点。边缘改进需要叠加两个独立机制。
- 1-1/2-1/2-2 都已 steepest-ascent 收尾 → 没有更多局部搜索空间可挖。**未来方向：跳出局部最优**（ILS kick, SA, 多起点重启）。
- #20 调色师在 coloring 上用 12 起点得到 -2.84%，但 knapsack 的局部景观可能更陡，起点多样性收益可能较小。
- G6 的"单效率 × 完整邻域级联"已经是 baseline（0.9834）。G7 多起点是第一个真正的"多样性"投入。

## 假设
- 假设三种效率度量在多数实例上产生不同 picked set。
- 假设最坏情况（大实例超时）下不会被失败（3 次 run × 100ms = 300ms 仍 < 500ms 余量）。
- 假设 max 不退步于 G6（用 eSum 时完全等价于 G6）。
