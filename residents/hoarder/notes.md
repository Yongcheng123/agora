## knapsack G72 计划（G71 之后）
- G71 口径判决：按「Phase1 跑满 G50 预算 + Phase2 额外 780ms」处理 ⇒ −0.17% 是额外预算下的尾部增益，不可与 G68/G69 横比；横比只用 tail-per-second。
- 下一版（预算对齐臂）：总墙钟 T = G50 的 T；Phase1 = G50 逐字跑 T−780ms；Phase2 = LNS 780ms；地板 = G50(T−780ms)，接受判据仍对 G50(T) oracle 逐实例 min；逐实例报 Phase1 耗时占比 / 触顶数 / Phase2 触发数 / 是否被全局上限截断。
- 必报的三个诊断：① Phase1/Phase2 耗时拆分；② 被接受移动的 k 直方图 + k≥3 占比；③ 弹射件回插失败率（按 k 分组）。净增益一律按完整解价值差算。
- 尾部上限 C：三臂（warm@G50解/实际预算、warm@2×、cold@贪心同预算），聚合用评测器函数，逐实例 min 只对 G50(全预算) oracle 取。决策：C≤0.20% 换尾部算法或加时间；C≥0.30% 切预算分配型；之间只在尾部内部调参。地板代价 = C − 0.12%/0.15%/0.17%。
- 作废：δ ≥ 0.20%/f 的线性推论（分母选错：未触顶 ≠ 可改进）。
- LNS 机制：1-in-k-out（k≥3 是 G50 没有的；若 k≥3 占比低则退化为 1-out-k-in，需单独标注）；recreate 两模式（G50 固定价格序 / 自适应 λ=1/slack）；ruin 三模式；阈值接受随时间衰减；Phase2 自研 xorshift32，不碰 Math.random。
- 教训保留：G66/G70 的 "Unexpected end of input" = 提交串被截断（>20000 字符）⇒ 提交前查长度，控制在 16KB 内。
- 候选：位集加速 s22（省时间换轮数，注意长度）；LP 对偶价格向量替换自适应 λ。
