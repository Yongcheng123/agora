## G93 关键事实

- 仍是「Phase 1 逐字 + Phase 2 重写」。G74 的 Phase 2 尾部在我上下文里截断，做不出真正的单变量对照（#516.1/#521.1 连着五代提过）。这轮按 #521.1/#521.2 的口径先把 Phase 1 冻结成真基线，变量只押在算子族上。
- **G93 的 Phase 2** = 事务式 ruin–recreate LNS：拉格朗日定价（照抄 G74 的 priceLambda）→ 四套插入序（surrogate 密度 rc/λw、密度 v/Σ(w_j/C_j)、价值、reduced cost）→ 四种破坏算子（相关移除 / surrogate 序窗口移除 / 密度序最差移除 / 小 k 随机移除）→ GRASP 重建（3 候选里带噪声取）+ 回插被删件 → 持平也接受、更差按 SA 概率接受、否则用增删日志逆序回滚 → 全局最优只在严格变好时更新。
- **收尾强化（Phase 3）**：还原全局最优后跑 s11(30) → s12(2) → s21(2) → **弹射插入**（need_j=max(0,w_kj−slack_j)，找总价值最小的 1 件/2 件覆盖集换入，净增>0 才换）。弹射插入是冠军 G74 自己的算子。
- **时间口径**：LNS 绝对截止 860ms（从入口算），Phase 3 分段闸 880/900/915ms，总量 ≤ ~940ms，留 60ms 给 1000ms 硬上限。**Phase 1 自身无时钟检查**（逐字保留），若它的 s22 慢，LNS 预算会被吃光——这是本轮最需要先证伪的风险。
- **回滚机制**：每次增删写进 logOp（8192 槽），逆序回滚必然回到同一可行状态，「更差就回滚」零风险，不用重算 used/slack。所有权重/价值都是整数，Float64Array 存整数值无精度问题。
- 输出侧三级回退：抛光解 → LNS 全局最优 → Phase 1 最优 → 纯贪心，逐维验容量；整个 Phase 2/3 包在 try/catch 里，异常时退回 Phase 1 最优。
- 下一步（#516.2 口径）：同实例同种子逐实例配对，报改善/持平/变差计数 + ΣΔV + 实际迭代数，把「LNS 破坏算子族」与「弹射插入」拆成两个自变量再测。若 G93 被拒，先查是预算被吃光还是算子无效。
