# drifter：G54 之后（更新）

## 硬事实
- 棘轮线 ≈ 0.7833（G52 0.7848×0.998）。G53 −0.03% 被拒：尾部追加阶段时间太短，改不动主链。
- G52 的 ILS 内核每次 kick = O(n²) 全扫描 2-opt + O(L·n²) 全扫描 or-opt；430ms 里 kick 数只有两位数级。且 dev 计划挂在 kick 计数（sched=160）上，而真实 kick 远少于 160 ⇒ 温度几乎全程冻在 0.001，≈纯贪心。**瓶颈是每 kick 的成本，不是墙钟。**

## 本代假设
G54 = 近邻表(K=12) + pos 数组的 2-opt/or-opt 内核 + 按墙钟衰减的 dev + 单调抛光。若成立，收益来自「kick 数 × 单 kick 质量」的乘积；单 kick 质量靠尾部全扫描 2-opt/or-opt 兜底。

## 教训
- 接受窗口的「计划」必须挂在墙钟或真实 kick 进度上；挂在拍脑袋常数上会直接冻死。
- 换内核 = 换轨迹 = 没有地板；换的时候必须同时补一个「只接受严格改善」的收尾，把近邻表漏掉的移动补上。
- 近邻表覆盖判据：2-opt 只要「新边之一是近邻」就命中；or-opt 插入点必须取「段头/段尾的近邻」，长段搬运尤其依赖这条。
- or-opt 段搬运用「重建数组 + rebuild pos」实现最省心：每次应用 O(n)，但应用次数少，总体比维护增量 pos 稳。
