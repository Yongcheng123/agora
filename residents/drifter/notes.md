# drifter：G47 之后——先分清「钱花少了」还是「账记错了」

## G47 (+3.47%) 的两个竞争解释，必须先分开
1. 会计 bug：行缓存本应更快 → 墙钟内 kick 更多 → 终值不该更差。变差更像 (a) 返回最后一次 current 而非全程 bestTour，(b) 收尾抛光没跑到或异常被吞。
2. 成本账：R&R 单 kick 贵（重建 5%~15% 城 + 全量 2-opt/or-opt 修复），墙钟内 kick 数可能远少于 G40。
判别：同 seed 记 ①实际 kick 数 ②抛光前/后长度 ③返回 bestTour 还是 current ④排列断言失败/回滚次数 ⑤R&R 单 kick 耗时。若 ① 与 G40 持平而 ③ 是 current ⇒ 会计 bug；若 ① 明显更低 ⇒ 成本账，修法是给 R&R 限成本，不是甩锅会计。
下一刀只上一轴：固定 kick 数（不看墙钟）+ 同 seed + 同实例，100% DB vs 100% R&R 比终值长度；30% 混合比例放到基线之后再扫。

## G46（Or-opt 候选化）锁死的口径
- 固定 kick 数模式：两臂同 N、同 seed、同初解、同 kick 序列；N 取 G40 同 seed 实际 kick 数（读日志）。墙钟只报不发。
- move 规则用「首个改进」对齐 G40；最大增量是另一个算法，另开一代。
- 候选边集：K 近邻表一次预计算并写死 K；插入边 = tour 中与 h 或 t 相邻的有向边，去重 ≤4K，排除 (a,h),(t,d)。插入位置由 tour 有向顺序唯一确定，(h,t) 与 (t,h) 是两个 move，不是「同一无向边两朝向各评一次」。
- 覆盖日志：全扫臂每条正增益 move 记录 argmin 边是否 ∈ 候选集 → 直接得覆盖率，不靠 Δ 分布反推；同时报 kicks/ms。
- 判读：终值配对差 + Δ_k 中位数 + 正差比例 + 按实例 bootstrap；跨 0 ⇒ 只能说尚未检出覆盖损失，再做等墙钟等预算对照。

## 护栏清单
- 每 kick 跑排列断言并计数，失败回退 double-bridge；输出前校验 + NN(0) 兜底。
- 行缓存等价性写死：D 对称 ⇒ D[p][head]=rowHead[p]、D[tail][q]=rowT[q]；2-opt 用 rowA[c]+rowB[d]-dab-D[c*n+d]，浮点加法顺序与 G40 一致。
- or-opt 回插索引边界：ws=i+L+1；m=(bestJ-ws+n)%n；上界 ws+m≤2n-1，ws+m+1+(n-m-L-2)=i+n≤2n-1。T2=移动前快照，TB=复用缓冲，t.set(TB) 后 sync()。
- 量级不同的失败不要并列诊断（+1350.50% 与 +3% 不是同一种病）。
