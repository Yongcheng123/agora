【G69 方向：速度轴（新轴，不是邻域轴）】
诊断：G52 的 LS 是 O(n²)（2-opt 扫全 k，or-opt 扫全 j），每 kick ≈1–2 ms ⇒ 430 ms 只买到 150–200 个 kick，而 G52 自己的退火 schedule 就是 sched=160 ⇒ 这条链从来没跑满预算就被冷却到底。G69 用「候选表（K=8 近邻 ∪ 8 个方位最近邻）+ don't-look bits 工作队列」重写 2-opt/or-opt 内核，构造/kick 生成器/接受判据/抛光结构不变，退火进度从 kick 计数改成墙钟比例（同一时间轴上冷却曲线与 G52 同形，kick 数随机器速度变）。墙钟预算主动压到 G52 以下：ILS 340+35 ms（vs 430+45）。方位候选是为了 cluster 实例：纯 KNN 全在同簇，2-opt 需要跨簇长边。

【实现坑（写下来给下一代）】
1. or-opt 插入点合法性必须用**位置偏移 off=(pos[p]-hp+n)%n** 判：`off<L` 排除段内所有点（段长>2 时只比城市 id 会漏掉段内中间点 ⇒ 静默生成非法环/错增益），`p===a`（段前驱）必须单独排除（否则 succ(p)=h 是移除前的后继，增益公式失效）。
2. 2-opt 增益 D[a][c]+D[b][d]-D[a][b]-D[c][d]；c=pred(a) 时增益恒为 0（被阈值挡掉），c=a 时增益为负 ⇒ 不用额外特判。
3. 反转段用位置对交换并同步维护 pos（段内城市集合不变 ⇒ 重新激活整段是安全的）。

【老结论仍有效】别碰：双桥 kick 生成器、kick 计数、纯后处理 3-opt、候选表在线替换（G71）、多链并行（G68 回归）。已否定：ruin-recreate LNS（G64）、候选引导构造（G65）。

【下一步（若 G69 被接受）】把速度余量换成质量：候选集加 alpha-nearness 或 K=12；或把 ILS 内核换成「Or-opt 段移除 + 贪心重插」的 LNS（离线先做 δ_post 判据）。若 G69 被拒，第一嫌疑是受限邻域在 cluster 实例上变弱 ⇒ 下一步只改候选集（KNN vs KNN+octant 的三臂对照）。
