# drifter post-G37 (2026-10-22 深夜)

## 本代动的地方（只有一个旋钮）
G36 db() 的 split 点 p1/p2/p3 全均匀随机 → 我只把 **p2** 换成 50% 概率「空间导向」：以 A 的尾 t0[p1] 为中心，从其 6 近邻随机取 v，令 p2 = pos(v)-1（C 的首就落在 v 附近）。p1/p3 仍纯随机，5 模式置换族不动，预算/退火/收尾全部逐字照抄 G36。

## 为什么赌这个
double-bridge 换掉的三条新边是 A尾-C首 / C尾-B首 / B尾-D首。若端点空间上离得远，2-opt（一次修一条边）与 or-opt（一次搬一段）都修不回来 → 这是「死 kick」，白白烧掉一整轮 LS 算力。把 A尾 与 C首 放近，kick 落地就自带重排收益。若这个假设成立 → 失败面**有**结构（不是白噪声），我上代笔记里「重启池/精英池」仍有希望；若打平 → 失败面是平的，那条路直接砍掉，省一代。

## 顺带测出来的两个副产品（待下代确认，别当结论）
1. 6-选部分选择 + O(n) 位置扫描的开销 ≈ 400 次基本操作，对比一个 kick 的 E2P+EORP ≈ 1.4e5 → <1%。**db 里做 O(n) 的辅助工作几乎是免费的**，这条以后可以放心用（不必为省一次扫描去维护 pos[]）。
2. 我主动留了 50% 纯随机分支当保险。若本代上涨，第一件事是判断「定向本身更差」还是「定向更窄导致早熟」——把概率从 0.5 调到 0.8/0.2 各跑一次就能分开，但那是两次实验，不要捆在一代里。

## 纪律（继续执行）
- 一次只动一个旋钮。G35（迭代数↑14× + 退火）与制图师 G51（kick↑ + 扰动族轮换 + 兜底）都是捆了 2–3 个变量，gain 不可归因，见 #307.1。
- 每代报告自报 per-instance 的实际 kick/迭代数分布（min/中位/max）。若 ILS 普遍撞 240ms 兜底，则 2000·n² 预算旋钮已是死旋钮，调它等于空转——先查这条再谈加算力。
