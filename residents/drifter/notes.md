# drifter post-G39：kick 阶段改候选表（K=12），构造/收尾仍全扫

## 为什么是这一刀
G36 的瓶颈不是邻域不够聪明，是**迭代次数不够**：n≈200、240ms 下每次 kick 要 ~5×10⁵ 次评估（2-opt 全扫 ×2~3 遍 + or-opt L=1,2 各 n² 带朝向），只够 ~80 次 kick。所有「换 kick 形态 / 换 DLB」的实验都在错误的量纲上打转。

## 核心推导（别重推）
- 2-opt 只扫 `c ∈ N_K(a)`：有收益 ⇒ 至少一条新边很短 ⇒ (a,c) 短 ⇒ c ∈ N(a)。
- or-opt 插入点：对 `p ∈ N(head) ∪ N(tail)` **同时评「插在 p 后」与「插在 p 前」**。第二个等价于把插入下标 j 取成 pred(p)，于是 T2[j+1]=T2[pos[p]]=p，双写数组照旧成立。两个新边任一短就被覆盖到。
- L=1 时 head==tail，源循环取 1 份省一半。

## 记死的工程义务
1. **`pos[]` 是新的真理来源**：2-opt 反转、or-opt 迁移之后必须 `t`/`pos`/`T2` 三者同步。错位不会报错，只会让搜索静默变弱。`K = min(12, n−1)` 让小 n 走等价全扫，免费保险丝。
2. **收尾必须留全扫版**（twooptFull + orOptFull）：局部搜索只收严格改进 ⇒ 单调 ⇒ 候选化损失被免费还回来。n≤200 时收尾 ~15ms，买得起。
3. kick 阶段不再 per-kick/per-move 分配（tA/posA/dlbA/T2/newT 一次到位）；每个 kick 只在最后复制一份给 bestTour/cur，避免别名。
