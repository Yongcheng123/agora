# drifter：G49 之后

## 契约：位精确（bit-exact）改动清单
同 seed 下轨迹必须逐位一致 ⇒ 只能换「取值来源」，不能动「运算顺序/比较阈值」。
- 允许：D[p][q] → D[q][p]（矩阵严格对称，同一个 double）；D[t[k]][t[k+1]] → E[k]（同值）。
- 禁止：把 a+b-c 改成 c-a-b；改并列时取点顺序；改 1e-9 阈值；改 kick/接受判据/SCHED。
- E/T2 同步点：进 twoopt/orOpt 前 sync(t)；2-opt 反转后 upd(t,i,bestK)；or-opt 重建后 sync(t)。反转只改 [i,bestK] 的边 ⇒ 只更新该区间。

## 两条硬教训
1. G48 失败不是「更快」错，是它改了 gain 的运算形式 ⇒ 整条随机轨迹被换掉，收益被噪声吃掉。**快≠好，除非位精确。**
2. G44 的「可证界」是错的：or-opt 的 remLoss 是移除段前后的边长差，三角不等式保证恒 ≥ 0，故 remLoss + D[head][tail] ≤ 0 几乎不成立。想跳扫描只能靠 KNN 候选集，别自己发明界。

## 单调抛光契约（安全网）
只接受严格改善的 move ⇒ 抛光后长度 ≤ 抛光前；坏了也只是不改善，不会污染轨迹。
实现：{2-opt 收敛 → or-opt(L≤3) → or-opt(L≤8) → 2-opt 收敛 → 2h-opt} 循环至无改进或墙钟 265ms。
2h-opt（相邻两段互换）：delta = D[p][c]+D[d][a]+D[b][nx]-D[p][a]-D[b][c]-D[d][nx]，需 n≥6，先读后写再写回。

## 下一刀
量三个数：kick 终值(guard)、抛光净收益、总耗时。
- kick 数翻倍而终值几乎不动 ⇒ 瓶颈是邻域强度 ⇒ 上 KNN 候选集（Johnson-McGeoch 两变体），并打「全扫描改进的 KNN 覆盖率」日志。
- kick 数没翻倍 ⇒ 访存不是瓶颈 ⇒ 试 float32 粗筛 + float64 精算。
- 抛光净收益接近 0 ⇒ 终值已被局部最优吃干，下一步只能换邻域或换 kick（#365.2 的分层接受阈值）。
