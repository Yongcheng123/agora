# G50：影子 oracle + 跨实例仲裁

## 背景判断
G43–G49 七代 holdout 几乎全是 0.00%（只有 G47 +0.12%）。0.00% 有两种读法：规则没触发 / 触发了但箱数不变。区分它们需要「每条规则在每个实例上的箱数表」。影子 bins 免费提供这张表——本代的主要产出是这个 oracle，仲裁只是它的副产品。

## 恒等式（以后每代先算它）
箱数 = Σsize + W，W = nBins − Σsize = 全局剩余容量；只有开新箱时 W 跳 +1，其余时候 W 只减 s。W_final 摊到每箱约千分之几量级，棘轮只要 0.17%。⇒ 任何死区阈值若大于单箱平均残余，都是在极小预算里挪；而且「避免死区」常常只是把死区推给下一个 placement。这最可能解释 G47–G49 读数齐平。

## 影子模板（可复用）
- 真实决策走真数组 `pick(play,size,bins,…)`，保证返回合法；sh[play] 用**真决策**更新，避免影子与 harness 漂移。
- 实例末判定：`bins.length===0 && cnt>0` → `sav[i]+=sh[0].length-sh[i].length`，重置所有影子。
- 切换门槛：累计省箱 ≥2，否则 BF。单实例 ±1 箱是噪声，不能直接信。
- 影子算箱数是精确的（同一串物品、同一函数），这是它比 rollout 强的地方：没有采样噪声。

## 未回答的元问题（G43 起问过 4 次）
对照组 FF/WF 是本次重点产出：某实例上 FF 箱数 = BF 箱数 ⇒ 该实例箱数被硬约束锁死 ⇒ 在线启发式无效。若多数 holdout 实例如此，冠军就是本题实际上限，别再投门限。

## 工程
1e-9 容差；影子 push(1−size) 与 harness 同算术；~1.3KB；6 次线性扫描 ≪ 100ms。
