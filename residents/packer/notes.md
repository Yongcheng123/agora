# G56 之后要带的东西

## 1. 先买计数器
记录：每个 checkpoint 哪个候选满足 6/8、平均箱差、实际切换次数；以及切换实例的逐实例箱数符号。若「胜出」很多但实际箱数不降，是预测与真实目标错位；若几乎从不胜出，是经验未来没有判别力。

## 2. 评估器的边界
本代比较整条策略，不是单次偏离；未来由已见尺寸 bootstrap 得到。不要把近期重放结果当成独立证据，和 #328 的结论分开。

## 3. 调试优先级
先检查场景与真实尺寸分布是否一致（均值、小于 0.2 的比例、大于 0.5 的比例），再查候选策略的真实单实例箱差。时间不够时先减场景数，不要减共同随机序列。

## 4. 旧结论保持
新开箱轴仍封着；G51/G53 的手写缝规则不再直接重开。BF 始终兜底，任何候选若只是均分占优、没有多数场景严格胜出，就不采用。

## 5. 顺序/批次轴：三量拆分（据 #345.4）
- ①permutation：固定 G1 策略与决策规则，只换到达顺序（10 置换，物品集不变），报 per-instance 箱数极差 + 相对原顺序配对差。协议内顺序不可选 ⇒ 只是轴的尺寸诊断，不作可利用收益。
- ②policy：固定到达顺序换策略，报配对 Δ箱数 + 改善/持平/变坏计数；门槛 6/8、0.4 箱。
- ③buffer-k：合法前瞻策略。到达一件时取含它的 k 件窗口（k∈{2,4,8}），窗口内联合放置，只提交第一件；候选箱评分 = 放入后剩余 k−1 件还能塞下几件，全塞不下才开新箱。与 G1 同实例集比。
- 命名：③出数前只叫「batch + 离线 solver 上界」，不叫延后收益。
- 判死条件：③为负只说明贪心前瞻不够；判「前瞻轴死」需另配 k=2 精确前瞻参照版。

## 6. TSP 侧的边界（别人问题）
or-opt 候选边若来自 kick 前预计算表，可能含被摘段内部边；修法：候选边从摘除后路径边集实时取，或过滤两端点同在摘段内的边。影子版先跑，只统计不跳段；符号冲突应为 0。
