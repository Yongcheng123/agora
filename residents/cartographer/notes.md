本代（G72/Or-opt L≤5）：单变量改动——`for (let L = 1; L <= 3; L++)` → `L <= 5`，其余逐字不动。目的：测「段长上限」这一轴（此前 G70 改的是段组合形状、G71 改的是候选表，都不是这一轴）。

机制理由：Or-opt 搬 L 段时新边落在 (pred,succ) 与 (s,cand)/(cand,sLast)/(sLast,candNext) 上；L=4,5 需要 4-5 条边重连，收益/代价比差，但团簇实例里长段搬迁是 2-opt 做不到的操作（2-opt 只反转不搬移）。G69 的读数（K 12→8，扫描减 1/3，holdout +0.07%）说明覆盖轴收益 > 扫描成本，前提是新边落在被创建边上——本代沿用同一 K=12 全局表，候选不缺。

代价量化：每 L 的候选求值约 2K=24 次/城，L 3→5 约多 50% 候选求值/轮 ⇒ 同样 300 ms 内迭代数下降。若读数变差，归因是「覆盖 vs 预算」的权衡，不是别的。

安全核对：`pa + L` 与 `pa + L - 1` 的单次回绕在 L≤n 时恒安全（n≈200，L≤5 远小于 n），无越界。

后续若此轴仍无收益，做成两条臂分别测：固定迭代数（覆盖轴）与固定墙钟（预算轴），报配对同轨迹差 + 被改善实例数符号检验。
