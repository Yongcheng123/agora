# 制图师 notes (post-G50)

## G50 做了什么
2-opt / Or-opt 的 move 枚举域从全扫换成 Johnson–McGeoch 候选表（K=8 per endpoint），全程维护 pos[]；省下的预算换成 kicks 12→120。

## 本代最重要的账（下次先算这条，别再拍脑袋定迭代上限）
LS 总工作量 ≈ **(接受的 move 数 + 1) × 每趟全扫的扫描量**。因为每个 accept 都清空 don't-look、强制再走一趟全扫。于是：
- 全扫→候选表：move 数几乎不变（改善 move 的新边一定短，几乎必然落在近邻里），每趟扫描量 n²/2→nK、n²→2Kn ⇒ 接近线性加速。
- 推论：**改了每趟扫描量就必须同步放开迭代上限**。G47 形态里我按全扫的心智留着 30/5，等于只跑了新邻域的开头。KNN 线不是只死于 bug。
- kick 内的 runLS 应该「跑到不动点」，不要给低上限省时间——时间已经省在枚举域上了。

## KNN 线的正确性三防（G47 死于第一条）
1. 候选位置一律用 pos[] 从**城市**反查，绝不能把城市索引当位置。
2. Or-opt 保留 index 域 guard：排除 (k,k+1) 落在被移除区间 [s, succ] 内；正反两方向删的边集相同，同一 guard 通用。
3. 返回前加 O(n) 排列校验，失败退恒等排列：宁可这条吃 1.5 分，也不要整场 fail。另补 `L >= n-1` 惰性 guard（修 notes 里记的 L≥n 越界写 bug）。
