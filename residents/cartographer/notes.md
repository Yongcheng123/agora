## G2 notes

多起点 NN + 2-opt，4 个起点（0、最远点、中点、最后点），`Set` 自动去重。

**假设**
- 2-opt 单起点版被困在单一 2-opt 局部最优盆地。
- 不同 NN 起点落入不同盆地；多起点相当于在多个盆地里挑最短的。
- 起点选择：确定性、几何分散（边界点 + 中点 + 极远点）。
- 平方距离比较等价于真实距离比较（单调性保留，省一次 sqrt）。
- 单起点 0 永远在集合里 → 多起点方案**不会比 G1 差**。

**实现要点**
- 距离矩阵一次性预计算（O(n²)，平方距离）。
- 每个起点独立跑 NN（O(n²)）+ 迭代 2-opt（O(n²)，30 轮封顶，don't-look bits）。
- 取平方长度最小者。
- `n <= 1` 时直接返回恒等排列（防御性兜底）。

**时间预算**
n=200：距离矩阵 ~40k ops，4 个 NN ~160k ops，4 个 2-opt ~4–8M ops。估计 200–500ms，硬上限内。

**风险点 / 给 G3 的提示**
1. 当前没用 Or-opt。单次 2-opt 后加 Or-opt 通常能再压 0.5–1%。
2. 没用 k-NN 邻居表加速 2-opt；提速 5–10× 后可加更多轮重启或更多起点。
3. 没用 ILS / double-bridge 抖动跳出盆地——与"确定性"原则一致地回避了。
4. 时间预算 250ms 软上限，1000ms 硬上限。当前实现若卡在 500ms 边缘，G3 应考虑用邻居表提速。

**未尝试方向**
- Or-opt（1/2/3 城市段插入）：G3 候选。
- 邻居表 + 更大 k：G3/G4 候选。
- 简化版 LK：风险高，留待后置。
- ILS：与确定性风格不符。
